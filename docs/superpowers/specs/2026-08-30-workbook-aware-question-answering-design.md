# 工作簿感知的多指标问题回答设计

## 目标

让数据分析 Agent 对真实 Excel 文件先定位可分析的表格，再针对用户点名的指标输出可核验的结论，而不是把封面页或数据质量说明当作分析结果。

## 已验证根因

`read_spreadsheet()` 固定使用 Excel 第一张工作表和第 1 行作为表头。`财务分析样例数据.xlsx` 的第一张工作表是封面说明；真正的月度财务表位于“财务汇总”工作表的第 3 行表头。随后 `QuestionPlan` 只选择一个数值列，因此无法回答同时要求营业收入、毛利率和营业利润的问题。

## 设计

### 1. 工作簿表格识别

Excel 读取器扫描每张工作表的前 12 行作为候选表头。候选表按以下条件打分：存在时间列、至少一个可转为数值的业务指标列、至少两条有效数据行、字段名不重复。选择得分最高的候选表，且将源工作表和表头行写入 DataFrame 属性，供结果页“数据”模块显示。CSV 保持现有读取方式。

### 2. 问题规划

`QuestionPlan` 将单一 `metric_column` 改为有序 `metric_columns`。它从用户问题中逐一匹配所有被点名的指标；若用户没有点名指标，再选择一个非 ID 的数值业务列。解析请求中的起止月份，并只在该区间内计算。对“趋势、异常、风险、预测”保留原有意图识别。

### 3. 结果生成

对每个已请求指标生成整体月度序列和对应摘要：起止值、累计变化、最近环比、最高/最低月。对环比绝对值显著高于该指标历史波动的月份标记异常。若营业收入、毛利率、营业利润同时存在，异常解释只能使用数据可支持的关系：收入与利润同向而毛利率基本稳定时，表述为“收入规模变化主导的可能性较高”；不得捏造客户、价格或业务事件。

核心结论必须直接覆盖用户所问的三项：趋势方向、异常月份、异常幅度与数据证据。关键数据按指标展示；详细分析只展示与请求意图有关的趋势与异常；质量信息继续折叠。趋势或异常请求至少生成一张包含三条指标序列和异常标记的核心图。

### 4. 完整性门禁与页面

在返回结果前，完整性检查要求每个请求指标都出现在核心结论和关键数据中；趋势与异常请求必须各有相应模块和图表。页面延续“核心结论 → 关键数据 → 详细分析 → 业务风险/建议 → 折叠数据质量”的顺序，并显示多指标关键数据，不新增与问题无关的固定模块。

## 验收

以测试者提供的财务样例文件和以下问题端到端运行：

> 分析 2024-01 到 2025-12 的营业收入、毛利率和营业利润趋势，指出异常月份及可能原因，并引用数据证据。

结果首屏必须含三个指标、具体月份和数值、趋势方向、异常幅度、基于指标联动的可能原因，以及至少一张图；数据质量默认折叠。原始 16 条验收标准保持有效，尤其是“用户问题优先”“图表不能为 0”“Tab 语义化、可省略、可滚动”。
