# 问题驱动分析结果与多任务标签重构设计

## 目标

将当前以数据质量、方法风险和固定方案为中心的结果，重构为以用户原始问题为中心的可验证答案。每次成功分析的结果首屏必须先给出具体结论、对象、数值证据和影响；数据质量与方法限制仅作为次要信息。多任务标签必须以语义化短标题呈现，支持清晰切换而不因长问题挤压失效。

## 范围与边界

- 支持电子表格中的趋势、异常、排名/对比、风险和预测问题；DOCX 保持“文本审阅”边界，不伪装为测量型数据分析。
- 使用确定性、可复算的 pandas/numpy/Plotly 分析；不调用模型生成的代码，也不把无法从数据判定的业务原因写成事实。
- 本次不新增外部模型、数据源或复杂图表编辑器；仅生成与问题类型匹配的核心图表。
- 高风险领域的人工复核边界保留，但不替代面向问题的结论。

## 根因与改造方向

现有 `engine.analyse_spreadsheet` 无视 `objective`，固定输出质量、数值范围、固定风险和固定建议；`build_charts` 也总是对第一个数值字段画一张趋势图。因此即使用户询问异常、排名或特定地区风险，结果仍不能回答问题。前端结果页又把“数据事实/风险项/图表”作为最显著信息，强化了错误优先级。

改造后由“问题识别 -> 数据字段解析 -> 问题专用计算 -> 结论完整性校验 -> 动态结果模块/报告”构成唯一主路径。质量检查独立返回，只有它会实质性影响某条结论时才在结论旁提示。

## 后端设计

### 问题意图与字段角色

新增问题解析层，输出：

- `analysis_types`：`trend`、`anomaly`、`ranking`、`risk`、`forecast` 的一个或多个；按关键词识别，未命中时默认 `overview`。
- `time_column`：优先匹配日期、时间、月份、月、date、time、month；可解析后排序。
- `metric_column`：优先匹配营收、收入、销售、金额、revenue、sales 等与问题相关的数值列；否则使用第一个数值列并在结论中引用真实字段名。
- `dimension_column`：优先匹配地区、区域、产品、业务、客户、region、product、customer 等分类字段；无匹配时使用可分组的非时间文本列。
- `question_title`：由分析对象和目的生成 4–10 个中文字符左右的语义标题，例如“地区营收风险”“月度营收预测”“产品销售异常”；不可用“分析任务1”。

同一标题第二次及以后创建时由存储层生成 `标题 · 2`、`标题 · 3`。复制任务也使用同一规则，而不是“副本”。完整 `objective` 永远保存在 Session 中。

### 可复算分析与结果合同

新结果合同增加以下字段：

- `core_conclusion`：直接回答问题的自然语言结论；每个关键断言包含对象、时间或比较范围及至少一个实际数值。
- `key_metrics`：首屏展示的对象、当前值、环比/累计变化、风险等级等有限指标卡。
- `sections`：依问题类型生成的有序模块。趋势为“趋势分析/关键拐点/趋势风险”；异常为“异常对象/异常时间/异常幅度”；排名为“地区排名/关键指标对比/稳定性分析”；预测为“历史趋势/预测结果/预测区间/关键风险”。
- `business_risks`：仅收录从数据发现的对象风险，包含等级、对象、量化证据、趋势方向，以及数据能支持时的原因线索。
- `data_quality`：行列数、缺失、重复与仅在确实影响的对象/时间范围内的限制，默认不进入首屏。

趋势分析按时间和维度分组，计算相邻周期环比、累计变化与线性趋势斜率，明确标注上升、下降或稳定。异常分析以同一对象的变化率和/或分组分布的稳健阈值定位对象、月份及幅度。排名分析按指标聚合后给出前后对象、数值和稳定性。风险分析选择证据最强的高风险对象并说明严重程度；不是数据质量风险。预测沿用时间切分与朴素基线对照，只在条件满足时给出每一步预测及 80% 区间；无法可靠预测时明确说明缺少哪个数据条件，不能伪造预测结果。

每个趋势、对比、排名、异常或预测意图都必须产生至少一张对应核心图：时间趋势图、分组柱图、异常标记图或历史+预测区间图。仅在数据本身不具备相应字段时返回明确的不可分析原因。

### 完整性闸门与报告

`validate_answer_completeness` 在最终保存前逐项验证：有直接答案、明确对象、数值证据；趋势有方向，异常有对象和幅度，风险有最高风险对象，预测有结果或可靠性不可得原因；不允许由数据质量/泛化建议作为主结论。未满足时，分析请求失败并返回可操作的具体缺失项，不能生成成功报告。

Markdown、HTML、DOCX 报告采用与结果页相同的信息优先级：核心结论、关键数据、详细分析、业务风险、建议、数据质量与限制。删除固定的“低损害方案”模板和无条件免责声明；建议必须由前述发现派生。

## 前端设计

结果页“结果”标签首屏依次显示：

1. 核心结论（一句话直接回答）；
2. 关键数据卡；
3. 由后端 `sections` 指定的详细分析；
4. 真实业务风险；
5. 针对性建议；
6. 默认折叠的“数据质量与分析限制”。

图表标签在可视化型问题有图时显示图表工件；没有图时显示后端提供的明确原因。旧的“数据事实/风险项/图表”KPI、固定“关键发现/风险清单/低损害方案”区块不再作为默认结构。

顶部任务栏中的每个标签设置 `min-width: 120px`、`max-width: 220px`；标题单行省略，原始完整问题通过 `title` 和可访问名称显示。选中标签使用加粗、背景和底部高亮，未选中标签降低对比度；标签容器保持横向滚动，并将普通滚轮转换为横向滚动。新增“全部任务”按钮，打开最近任务列表并选择会话。关闭按钮不触发标签切换。

## 验收与测试

后端以一份含地区、月份和营收的可控数据覆盖：趋势回答方向、异常回答对象和幅度、风险指出最高风险地区、预测输出数值或区间、每条重要结论有真实数字、匹配问题生成图表、质量信息不作为主结论、标题语义化与去重。前端以真实 API 形状覆盖：结果首屏顺序和折叠质量区、动态模块、完整问题 Tooltip、截断样式类、选中态、横向滚动与全部任务切换。

最后执行独立对抗性审查：故意使用长问题、多任务、无时间列的预测、无维度列的异常、缺失影响关键月份的数据，以及一个“地区营收异常风险”样本。逐项映射原始 16 条验收标准，任何未满足项都必须修复后再报告。
