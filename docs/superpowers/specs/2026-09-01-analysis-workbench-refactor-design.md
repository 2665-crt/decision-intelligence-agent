# 数据分析工作台重构设计

## 目标

把当前 Session 分析页面收敛为一个可缩放、各区域独立滚动的工作台。每次成功分析都应在结果、图表、数据、Notebook、报告和文件标签中呈现同一个 Session 的数据；其中“问题 → 已验证回答 → 可解释图表”必须形成闭环。

## 已确认的根因

- `backend/studio_api/engine.py` 在结构化分析完成后固定写入 `charts: []`，即使 `findings` 已有可作图的数据，图表标签也不会得到内容。
- 前端 `body` 使用 `min-width: 1080px`，且结果与卡片链路未完整允许 Flex/Grid 子项收缩；`.core-conclusion` 同时使用加粗正文，窄宽下既难读又会溢出。
- `.history-pane` 是整个左栏的滚动容器，不存在固定操作区和独立会话列表滚动区；当前会话接口也一次返回全部历史任务。
- `Evidence` 默认直接渲染来源行与输出值，导致主结论被冗长的证据吞没。

## 范围与约束

- 保留既有 `GET /api/sessions` 返回列表的兼容行为；新增分页端点，不改变当前 Session、报告和下载路由。
- 只基于执行器已验证的 finding 生成图表；不可从自然语言臆造数值，无法生成时必须返回原因。
- 不新增第三方图表依赖。前端用受控 SVG 渲染 line、bar、stacked-bar、donut 和 scatter 的规格；异常以基础趋势图上的标记呈现。
- 正文始终自动换行；只有表格、代码、长 JSON、来源行等结构化内容可在自己的容器横向或纵向滚动。
- 不增加深色模式；项目当前未提供深色模式。现有浅色模式滚动条必须低干扰。
- 不触碰运行日志、数据目录或用户未跟踪文件。

## 数据流与接口

`engine.run()` 仍执行受控计划与校验，随后调用新图表规格构建器。构建器消费已验证 findings，把趋势、分类对比、占比、相关性和异常结果转换为：

```python
{
  "id": "trend-revenue",
  "title": "营业收入月度趋势",
  "type": "line",
  "x_label": "期间",
  "y_label": "营业收入",
  "series": [{"name": "营业收入", "points": [{"x": "2025-01", "y": 3158.7}]}],
  "markers": [{"x": "2025-03", "label": "异常", "kind": "anomaly"}],
  "unavailable_reason": null
}
```

每一个有效指标生成一张图，而不是把量纲不同的多个指标硬放到同一坐标轴。若只有不可图形化的 finding，返回一张带 `unavailable_reason` 的规格；图表标签显示原因和补充字段建议，不能空白。

后端增加 `GET /api/sessions/page?offset=0&limit=40&search=`，返回：

```json
{"items": [], "next_offset": 40, "has_more": true}
```

历史栏首次读取 40 条，临近底部时继续加载。选择、创建、重命名、复制和删除后局部同步已加载列表。现有 `GET /api/sessions` 继续保留给现有调用和测试。

## 前端信息架构

工作台维持三栏：左侧历史、中央任务对话、右侧结果标签。根容器占用 `100dvh` 并裁剪页面级溢出；每个栅格子项使用 `min-width: 0`、`min-height: 0`。左右分栏继续使用现有 pointer resize 与持久化宽度，列的最小宽度改为 `minmax(0, …)`，使 900px 等窄窗口也能按可用空间重新排版。

左栏改为 column flex：顶部的新建与搜索不滚动；中部 `.history-list` 是唯一纵向滚动区；不创建目前不存在的用户底栏。列表用 `useRef` 保存 `scrollTop`，Session 选择和加载下一页不会重置它；新任务只有在当前用户接近列表顶部时才自然显示在可见区。

右栏的 tab header 固定，`.result-panel` 独立纵向滚动。直接回答使用普通 16px/400 正文、1.7 行高和 `overflow-wrap: anywhere`；不以 `overflow: hidden` 或省略号裁剪。Markdown式普通文本、段落、列表均继承这条规则；表格、pre/code 和 JSON 分别包在结构化滚动容器里。

## 结果与证据

结果页依序展示：直接回答、状态、关键指标、已验证发现、限制。每个发现保留简短结论，证据改用语义化 `<details>`，默认关闭。一级“查看数据证据”包含来源、字段与筛选；计算过程、来源行、输出值和置信度为二级折叠。来源行与 JSON 限定最大高度、等宽字体和内部滚动，避免撑高整个结果页。

## 验收

- 趋势、多指标趋势和异常问题分别生成全量指标图及异常标记；无图条件可见解释。
- 结果初始页面不直接显示来源行和输出 JSON；二级展开后在自身容器滚动。
- 900px 至宽屏、80% 至 150% 缩放、拖动左右分栏与全屏结果时，普通中英文、日期、长字段名均完整换行且无正文横向滚动。
- 5 条历史不出现强制滚动条；超过可视高度时仅 `.history-list` 滚动，选择任务不重置位置，分页不会使页面变长。
- 后端测试、前端 Vitest 和 Vite build 全部通过，并用浏览器验证一个真实分析 Session。
