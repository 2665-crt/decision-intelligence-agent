# 多文件数据分析与 Notebook GUI 设计规格

日期：2026-08-01

状态：已通过交互设计评审，等待书面规格复核

目标系统：本地自部署 Dify + 独立数据分析工作台 + analysis-executor

## 1. 目标

在现有 Dify 数据分析能力之上建设一个独立本地 Web 工作台，使用户可以：

- 同时上传并准确读取多个 CSV、XLSX、DOCX 文件；
- 手动确认本次分析使用的文件；
- 使用 DeepSeek Agent 生成可编辑的单元格式 Python Notebook；
- 选择自动执行、只生成代码或取消；
- 在隔离环境中处理完整文件并生成真实图表；
- 查看静态与交互式图表、数据表、日志和分析报告；
- 修改代码、重新运行、自动修复、完全重建或返回更换文件；
- 只有在用户明确满意后发布精确修订的下载链接。

本规格描述目标产品，不表示这些新增功能已经部署。现有 Dify 单文件工作流和已验证的图表迭代能力仅作为后端基线。

## 2. 范围

### 2.1 包含

- 最多 5 个文件；
- CSV、XLSX、DOCX；
- 单文件最大 50 MB，单次总量最大 200 MB；
- 多文件独立校验、手动选择及完整/分块解析；
- 三栏 Web 工作台；
- 单元格 Notebook；
- Python 代码编辑、单元格运行、运行全部、停止、恢复生成版本；
- PNG、SVG、Plotly HTML、表格；
- Markdown 报告预览及 DOCX、PDF 下载；
- 不可变修订、历史版本、自动修复和发布；
- Agent 自动准备缺失依赖；
- 默认断网与按任务受控联网。

### 2.2 不包含

- 修改 Dify 官方前端；
- 嵌入完整 JupyterLab 或提供长期驻留 Python 内核；
- 允许用户代码直接控制 Docker、宿主机或任意网络；
- 未经用户要求自动合并多个文件；
- 把现有单文件工作流视为本功能已完成的证据。

## 3. 已确认的关键决定

1. 采用独立分析工作台，通过 API 复用 Dify Agent、Workflow 和 analysis-executor。
2. 使用三栏布局：左侧文件、中间对话与结果、右侧 Notebook。
3. Notebook 使用单元格模式，一个分析任务对应一个 Notebook。
4. 用户手动勾选本次使用文件；系统不得自动增加文件。
5. 选择后固定展示“本次使用文件”，并提供“返回修改文件”。
6. 更换文件后创建新的文件选择快照和修订，旧结果保留。
7. 每次任务无论文件大小均显示三个执行选项。
8. 运行结果采用混合展示：单元格下展示缩略结果，中间区域展示完整结果。
9. 代码失败后 Agent 自动修复并重试最多 2 次。
10. 支持 PNG、SVG 和 Plotly 交互式 HTML。
11. 报告支持 Markdown 预览、DOCX 和 PDF 下载。
12. 缺少包时由 Agent 自动准备依赖，用户不执行安装操作。
13. 普通文件分析默认断网；需要外部数据时使用任务级域名白名单。

## 4. 总体架构

### 4.1 独立分析工作台

职责：

- 用户、会话和任务界面；
- 文件上传、校验状态和手动选择；
- 分析需求输入和执行方式选择；
- Notebook 编辑与运行控制；
- 结果、报告、历史版本和发布展示；
- 通过稳定 ID 调用后端，不直接执行用户代码。

### 4.2 Dify Agent 与 Workflow

职责：

- DeepSeek 理解用户需求；
- 根据已确认文件的结构概况生成分析计划与代码；
- 需要自主选择、迭代或决定下一步时使用 Agent；
- 固定的文件解析、执行、产物整理和发布链路使用 Workflow/Tool；
- 根据执行日志自动修复代码，最多 2 次；
- 生成报告内容，但报告中的数据与结论必须来自实际执行结果。

### 4.3 文件服务与 analysis-executor

职责：

- 验证当前用户对 Dify 上传文件的访问权；
- 将文件流式保存到任务专属存储；
- 记录 SHA-256、格式、大小和解析结果；
- 在临时容器中运行完整文件；
- 管理依赖环境、任务级网络策略和资源限制；
- 保存不可变修订、日志及产物；
- 生成绑定精确修订的签名预览和下载链接。

### 4.4 安全边界

- 只有受控执行器/容器编排服务持有创建临时容器的权限。
- 用户代码容器不能访问 Docker Socket、宿主机路径、宿主环境变量或特权模式。
- 输入目录只读；输出只能写入当前修订目录。
- Dify 不直接把完整大文件塞入模型上下文。
- 模型不得猜测文件路径；代码只使用系统提供的 `FILES` 映射。

## 5. 三栏工作台

### 5.1 顶部任务栏

显示：

- 工作台名称和当前任务名称；
- 当前修订号及总修订数；
- 任务状态；
- 保存入口和任务菜单。

### 5.2 左侧文件栏

包含：

- 上传按钮与数量、容量限制提示；
- 每个文件独立卡片；
- 文件名、类型、大小、SHA-256 摘要；
- CSV 编码、分隔符、行列数和字段概况；
- Excel 工作表、行列数、公式、隐藏表及合并单元格概况；
- DOCX 标题、段落、表格和图片数量；
- 上传、校验、解析、失败状态；
- 手动选择复选框；
- “本次使用文件”清单；
- “返回修改文件”按钮。

至少选择一个成功解析的文件后才能继续。失败文件不能选择。

### 5.3 中间对话与结果区

顶部标签：

- 对话；
- 结果；
- 报告；
- 历史版本。

结果区支持：

- Plotly 交互式图表；
- PNG/SVG 预览与下载；
- 数据表；
- 完整运行日志；
- Markdown 报告；
- DOCX/PDF 下载；
- 当前结果所使用的文件、运行和修订信息。

底部保留对话输入，可用于修改图表、要求生成报告、完全重建或继续修复。

### 5.4 右侧 Notebook

工具栏：

- 运行全部；
- 停止；
- 恢复 Agent 生成版本；
- 新增单元格。

单元格能力：

- 编辑 Python 代码；
- 运行单个单元格；
- 复制、折叠、上移和下移；
- 显示成功、运行中、失败和待运行状态；
- 显示缩略图、关键日志、表格摘要和“在结果区打开”；
- 标记代码来自 Agent 还是用户修改。

三栏分隔线可拖动。左栏与右栏可折叠，中间区域始终保留。

## 6. 完整用户流程

### 6.1 上传与解析

1. 用户上传 1–5 个文件。
2. 系统分别上传、校验和解析。
3. 文件损坏、加密、伪装或超限时，只阻止对应文件或本次上传。
4. 大文件采用分块统计和索引；执行代码仍处理完整原始文件。

### 6.2 手动选择文件

1. 用户勾选至少一个文件。
2. 系统创建不可变 `selection_id`。
3. 下一步始终展示“本次使用文件”。
4. 返回更换文件时保留分析需求，创建新的 `selection_id` 和修订。
5. 旧文件版本保留，但明确标记为旧选择。

### 6.3 分析需求与统一三选项

用户填写分析需求后，无论文件大小都必须选择：

1. **生成并执行代码，直接查看结果**：生成 Notebook 后立即隔离执行。
2. **只生成代码，由我运行**：生成 Notebook，不执行；用户检查或修改后运行。
3. **取消本次分析**：不生成、不执行；保留文件与需求。

未经选择不得生成或执行代码。

### 6.4 单元格执行

- 一个任务对应一个 Notebook。
- 单元格按读取、处理、可视化和报告组织。
- 运行单个后置单元格时，在新临时容器中自动重放其前置依赖。
- 不提供长期驻留内核；所有运行必须可复现。
- 点击停止后立即终止临时容器，并保留代码与已生成日志。

### 6.5 结果与迭代

- 成功运行产生不可变成功修订。
- 普通修改进入 `refine_visual`，可沿用已确认的数据上下文与上一版方案。
- “完全不满意、推倒重来”等明确表达进入 `rebuild_visual`，保留数据上下文但不沿用上一版图表代码。
- 失败修订不得覆盖 `current_success_revision`。
- 更换文件必须创建新选择和修订，不允许继续使用旧运行状态。

### 6.6 报告

- 用户明确要求时才生成分析报告。
- 报告可使用 CSV、XLSX、DOCX 的实际解析内容和执行结果。
- 报告单元格位于同一 Notebook。
- Markdown 在中间区预览；DOCX、PDF作为产物下载。
- 报告必须记录来源文件和修订，不能凭空生成数据结论。

### 6.7 发布

- 只有用户点击“满意并发布”才生成正式下载链接。
- 发布必须绑定精确 `revision_id`。
- 任务部分失败时不得整体发布。
- 链接过期后按同一修订重新签名，不重新运行分析。

## 7. 文件读取正确性

每个文件都必须生成独立读取记录：

- `file_id + SHA-256` 固定文件身份；
- 读取前后哈希一致；
- 保存原始文件名、大小、类型和上传时间；
- CSV 检测编码、分隔符、字段数、异常行和缺失情况；
- Excel 检查全部工作表，包括隐藏工作表，并记录行列数、公式、合并单元格；
- DOCX 检查标题层级、段落、表格和图片；
- 展示完整读取、分块读取或读取失败；
- 执行代码通过 `FILES["file_id"]` 或等价受控映射访问；
- 每个产物记录来源文件。

“正确读取”表示文件按其格式完整或分块解析，并通过校验；不表示模型上下文包含每一行。完整文件由执行器处理。

## 8. 依赖包自动处理

### 8.1 基础镜像

预装常用数据分析与报告包，包括但不限于：

- pandas；
- numpy；
- matplotlib；
- seaborn；
- plotly；
- openpyxl；
- python-docx；
- kaleido；
- reportlab。

Agent 生成代码前获得当前环境的依赖清单。

### 8.2 自动安装流程

1. 执行器在运行前扫描 import。
2. 发现缺包后，Agent 自动调用依赖准备工具。
3. 独立依赖构建服务解析包名、Python 版本和平台。
4. 构建服务从配置的软件包索引下载，固定版本并校验哈希、兼容性与安全策略。
5. 生成只读 wheel 层或镜像层，保存 `dependency_lock`。
6. 自动重新运行原单元格。
7. 相同锁定环境可复用缓存。

用户不执行安装命令，也不处理版本选择。

### 8.3 无法安装时

- Agent 自动改用已安装的等价库并重新生成代码。
- 依赖安装和替代代码均失败时停止，保留代码及日志并说明原因。
- 失败不产生成功修订。

用户代码中不得直接运行任意 `pip`、`conda`、下载脚本或未受控二进制安装。

## 9. 网络策略

### 9.1 默认离线

仅分析用户上传文件时，用户代码容器不开放外部网络。缺失依赖由独立依赖构建服务解决。

### 9.2 任务级受控联网

当用户需求明确要求访问外部 API 或在线数据：

1. Agent 从需求和代码生成当前任务的域名白名单；
2. 仅允许 HTTPS 和明确端口；
3. 所有请求经过出口代理；
4. 禁止 localhost、私网、云元数据、任意 IP、通配域名和未批准重定向；
5. 任务结束后白名单失效；
6. 记录域名、时间、方法、状态码、响应大小和用途；
7. 不记录密钥、Token 或完整敏感请求正文。

### 9.3 数据外发

只有用户需求明确要求将指定数据发送给指定 API 时才允许。Agent 不得隐式上传文件、数据表、日志或报告。

凭据通过受控引用交给请求代理，不能写入生成代码、日志或 Notebook。

## 10. 自动修复

代码失败后：

1. 保存原始代码、错误日志和失败修订；
2. Agent 根据日志生成修订代码；
3. 自动重新执行；
4. 最多自动修复 2 次；
5. 两次仍失败则停止；
6. 用户可直接编辑代码重跑，或要求 Agent 继续修复；
7. 所有尝试均可查看，且不覆盖上一个成功修订。

依赖缺失的自动安装属于环境准备，不占用代码修复次数；安装失败后改写代码的尝试计入修复次数。

## 11. 核心数据契约

### 11.1 实体

- `AnalysisTask(task_id)`：用户、会话、需求、状态、当前成功修订。
- `UploadedFile(file_id)`：文件元数据、SHA-256、存储引用、解析记录。
- `FileSelection(selection_id)`：用户确认的不可变 `file_id[]` 快照。
- `Notebook(notebook_id)`：单元格顺序、生成版、用户编辑版、依赖、`selection_id`。
- `Cell(cell_id)`：代码、类型、依赖、用户修改标记、最近状态。
- `Run(run_id)`：运行范围、重放计划、状态、日志、修复轮次、网络与依赖锁。
- `Revision(revision_id)`：代码、文件选择、成功/失败状态和运行快照。
- `Artifact(artifact_id)`：产物类型、来源单元格、运行、修订和下载信息。

身份链：

```text
task_id → selection_id → notebook_id → run_id → revision_id → artifact_id
```

### 11.2 关键接口

- `POST /files`：上传并返回 `file_id` 与校验状态。
- `POST /selections`：提交用户勾选的 `file_id[]`，返回不可变 `selection_id`。
- `POST /notebooks/generate`：提交 `selection_id`、需求和执行方式，返回 Notebook。
- `POST /runs`：提交 Notebook、目标单元格与代码快照，返回 `run_id`。
- `POST /runs/{run_id}/stop`：停止运行并保留日志。
- `POST /revisions/{revision_id}/publish`：发布精确修订。

运行进度、单元格状态、自动修复、依赖准备和产物事件使用事件流推送。

### 11.3 不变量

- 每次运行必须绑定 `selection_id`。
- 模型不能增加未选文件。
- 失败运行不能改变当前成功修订。
- 每个产物必须能追溯到文件、单元格、运行和修订。

## 12. 错误处理

### 12.1 文件错误

- 损坏、加密或格式伪装：标记失败并禁止选择；其他文件继续可用。
- CSV 编码或分隔符不确定：展示候选解析，用户确认后才能选择。
- Excel 公式无缓存：提示只能读取公式文本，并建议重新保存文件。
- 超出数量或容量：上传阶段阻止并指出准确超限项。
- 某文件失败：其他文件不受影响，但引用失败文件的任务不得继续宣称成功。

### 12.2 模型、执行和产物错误

- DeepSeek 超时：保留文件、需求和 Notebook 草稿，允许重试。
- 代码错误：按自动修复规则处理。
- 超时、内存不足或用户停止：销毁容器并保留代码、日志和旧成功修订。
- 部分产物失败：成功产物可预览，但任务标为部分失败且不得整体发布。
- 发布失败或链接过期：按原修订重新生成链接，不重跑分析。

### 12.3 依赖与网络错误

- 缺包：Agent 自动安装并重试。
- 包不兼容：Agent 改用等价库；仍失败则停止并保留记录。
- 白名单域名无法访问：保留网络审计信息，Agent 可重试或改用上传数据。
- 请求重定向到未批准域名或内网：立即拒绝并记录安全事件。

## 13. 资源限制

每次运行必须设置：

- CPU 上限；
- 内存上限；
- 执行时间上限；
- 进程数上限；
- 单个产物与总输出大小上限；
- 临时容器和任务输出的清理周期。

具体数值由实施阶段根据目标机器资源确定，但限制机制本身是必需验收项。

## 14. 验收标准

1. GUI 可上传 1–5 个 CSV/XLSX/DOCX，第 6 个被阻止，前 5 个不丢失。
2. 单文件超过 50 MB 或总量超过 200 MB 时提示准确，不能绕过。
3. 用户必须手动选择至少一个文件；系统不自动增加文件。
4. 进入下一步后显示“本次使用文件”，可返回修改并保留分析需求。
5. 更换文件产生新的 `selection_id` 和独立修订，旧结果可查看但不串用。
6. 无论文件大小都出现“生成并执行 / 只生成代码 / 取消”；未经选择不生成、不执行。
7. 两个 Excel 可分别生成对应图表，也可按用户明确要求跨文件分析；不得隐式合并。
8. CSV、XLSX、DOCX 混合上传可生成图表和报告，报告引用真实执行结果。
9. 单元格 Notebook 支持编辑、运行单个、运行全部、停止、恢复生成版和调整顺序。
10. 运行后置单元格时，新容器自动重放依赖，结果与运行全部一致。
11. 单元格下显示缩略输出和关键日志，中间结果区显示完整结果。
12. 支持 PNG、SVG、Plotly HTML；交互图可缩放、悬停并下载。
13. 支持 Markdown 报告预览和 DOCX、PDF 下载，全部绑定正确修订。
14. 代码失败后 Agent 自动修复最多 2 次，所有尝试、代码和日志可查看。
15. 缺少 matplotlib 等依赖时，Agent 自动准备依赖并继续，用户不执行安装操作。
16. 包无法安装时，Agent 自动使用等价库；仍失败时保留完整记录。
17. 普通上传文件分析不产生外部网络请求。
18. 明确需要外部 API 时，只允许当前任务白名单中的域名和端口。
19. localhost、私网、云元数据、任意 IP 和未批准重定向均被拒绝。
20. 未明确要求外发时，上传文件、数据、日志和报告不能发送给外部 API。
21. 用户代码不能访问 Docker Socket、宿主机、宿主环境变量或特权模式。
22. 代码超时、内存不足或用户停止后，容器被销毁，旧成功版本保留。
23. 失败修订不能覆盖上一个成功修订。
24. 用户未点击“满意并发布”时，不生成正式下载链接。
25. 发布必须绑定精确 `revision_id`；链接过期后重签名不重跑分析。

只有以上验收全部通过，才能宣称“多文件 + Notebook GUI”已经完成。

## 15. 实施分解建议

本设计适合拆分为以下实施阶段：

1. 文件服务、选择快照和多格式解析；
2. 核心任务、Notebook、运行、修订与产物数据模型；
3. 三栏工作台和事件流；
4. 单元格依赖重放与隔离执行；
5. Dify Agent/Workflow 工具契约；
6. 自动修复、依赖构建服务与缓存；
7. 任务级受控联网和凭据代理；
8. 报告、发布与完整端到端验收。

实施计划必须逐阶段提供可运行的验证证据，不得用后端单元测试替代三栏 GUI 和真实文件端到端验收。
